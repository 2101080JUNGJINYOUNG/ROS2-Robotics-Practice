## 1. 실습과제1 (pubpub/src/cam_pub_node.cpp, main.cpp)

다음은 카메라(또는 영상 파일)를 읽어 압축 이미지를 발행하는 노드이다. 이전 챕터들의 `rclcpp::Node` 사용 방식과 비교해서 이 코드의 구조가 어떻게 다른지 설명하시오.

```cpp
// cam_pub_node.cpp
#include "pubpub/cam_pub_node.hpp"

using namespace std::chrono_literals;

CamPubNode::CamPubNode(
    const std::string & node_name,
    const std::string & topic_name,
    const std::string & video_source)
: Node(node_name),
  qos_profile_(10),
  video_source_(video_source)
{
    qos_profile_ = rclcpp::QoS(rclcpp::KeepLast(10));

    publisher_ = this->create_publisher<sensor_msgs::msg::CompressedImage>(
        topic_name, qos_profile_);

    cap_.open(video_source_);

    if (!cap_.isOpened()) {
        RCLCPP_ERROR(this->get_logger(), "Could not open video source: %s", video_source_.c_str());
        throw std::runtime_error("Could not open video source");
    }

    timer_ = this->create_wall_timer(
        33ms,
        std::bind(&CamPubNode::publish_frame, this));
}

void CamPubNode::publish_frame()
{
    cap_ >> frame_;
    if (frame_.empty()) {
        RCLCPP_ERROR(this->get_logger(), "Frame empty (video end or read error)");
        rclcpp::shutdown();
        return;
    }

    std_msgs::msg::Header header;
    header.stamp = this->now();

    auto msg = cv_bridge::CvImage(header, "bgr8", frame_).toCompressedImageMsg();

    publisher_->publish(*msg);
}
```

```cpp
// main.cpp
#include "rclcpp/rclcpp.hpp"
#include "pubpub/cam_pub_node.hpp"

int main(int argc, char * argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<CamPubNode>();
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

18~20장에서는 `auto node = std::make_shared<rclcpp::Node>("이름")`처럼 `rclcpp::Node`를 그대로 사용하고, 콜백 함수는 `std::bind`로 `node`와 필요한 객체들을 넘겨받는 평범한 전역 함수로 작성했습니다. 반면 이 코드는 `class CamPubNode : public rclcpp::Node`처럼 `Node`를 상속받는 클래스를 직접 정의하고, 퍼블리셔(`publisher_`)와 타이머(`timer_`), 카메라(`cap_`) 등을 모두 이 클래스의 멤버 변수로 갖습니다. 콜백 함수 `publish_frame()`도 멤버 함수이므로, `std::bind(&CamPubNode::publish_frame, this)`처럼 멤버 함수 포인터와 `this`를 함께 바인딩해서 타이머 콜백으로 등록합니다.

이렇게 클래스로 캡슐화하면 생성자에서 노드 이름, 토픽 이름, 영상 소스 경로를 인자로 받아 `CamPubNode("campub_7", "image/compressed", "영상경로.mp4")`처럼 여러 설정으로 재사용할 수 있고(주석 처리된 예시가 이를 보여줍니다), 카메라 관련 상태(`cap_`, `frame_`)가 전역 변수가 아니라 객체 안에 안전하게 캡슐화된다는 장점이 있습니다. `main.cpp`는 이 클래스를 `std::make_shared<CamPubNode>()`로 생성해 `rclcpp::spin(node)`으로 대기시키는 것으로 끝나, 로직 대부분이 클래스 내부로 옮겨간 구조입니다.

</details>

## 2. 실습과제2 (subsub/src/vision.cpp) — 라인 검출 전처리

다음은 `subsub` 노드가 이미지 한 장을 받을 때마다 실행하는 전처리 코드 일부이다. 각 단계가 왜 필요한지 순서대로 설명하시오.

```cpp
CamSubNode::CamSubNode() : Node("camsub_wsl")
{
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)).best_effort();

    subscription_ = this->create_subscription<sensor_msgs::msg::CompressedImage>(
        "image/compressed_7", qos_profile, bind(&CamSubNode::mysub_callback, this, _1));
    // ...
}

void CamSubNode::mysub_callback(const sensor_msgs::msg::CompressedImage::SharedPtr msg)
{
    Mat frame = imdecode(Mat(msg->data), IMREAD_COLOR);
    if (frame.empty()) {
        RCLCPP_WARN(this->get_logger(), "frame empty!!!");
        return;
    }

    Mat gray, binary, resizedBinary;
    cvtColor(frame, gray, COLOR_BGR2GRAY);

    Rect roi(0, gray.rows * 3 / 4, gray.cols, gray.rows / 4);
    resizedBinary = gray(roi);

    threshold(resizedBinary, binary, 0, 255, THRESH_BINARY | THRESH_OTSU);

    Mat labelImage, stats, centroids;
    int nLabels = connectedComponentsWithStats(binary, labelImage, stats, centroids, 8, CV_32S);
    // ...
}
```

<details>
<summary>정답 보기</summary>

먼저 `imdecode(Mat(msg->data), IMREAD_COLOR)`로 `pubpub`이 압축해서 보낸 JPEG 바이트를 다시 컬러 이미지(`Mat`)로 복원합니다. QoS는 `best_effort()`(UDP 방식)를 사용해 일부 프레임이 유실되더라도 지연을 줄이는 실시간 영상 처리에 맞춘 설정입니다.

`cvtColor(frame, gray, COLOR_BGR2GRAY)`는 컬러 정보를 버리고 흑백(명암)만 남깁니다. 라인 검출에는 "밝은 바닥과 어두운 선"의 명암 차이만 필요하므로, 흑백으로 바꾸면 이후 연산이 단순해집니다.

`Rect roi(0, gray.rows * 3 / 4, gray.cols, gray.rows / 4)`로 이미지 아래쪽 1/4 영역만 잘라냅니다. 라인 트레이서 로봇은 바로 앞의 바닥 라인만 보면 되므로, 화면 위쪽(멀리 있는 배경)을 분석에서 제외해 연산량을 줄입니다.

`threshold(resizedBinary, binary, 0, 255, THRESH_BINARY | THRESH_OTSU)`는 흑백 이미지를 검은색/흰색 두 값만 갖는 이진 이미지로 바꿉니다. `THRESH_OTSU`를 쓰면 임계값(threshold)을 사람이 직접 정하지 않아도 이미지의 밝기 분포를 분석해 자동으로 최적값을 찾아주므로, 조명이 바뀌는 실제 환경에서도 비교적 안정적으로 라인과 배경을 구분할 수 있습니다.

마지막으로 `connectedComponentsWithStats`는 이진 이미지에서 서로 붙어 있는 픽셀 덩어리(블롭)들을 각각 하나로 묶어 위치·크기·중심점을 계산해줍니다. 이 결과로 "라인처럼 보이는 덩어리가 몇 개, 어디에 있는지"를 알아낼 수 있습니다.

</details>

## 3. 실습과제3 (subsub/src/vision.cpp) — 라인 선택과 에러 계산

앞선 단계에서 여러 개의 블롭(덩어리)이 검출될 수 있다. 다음 코드가 그중 하나를 "지금 따라갈 라인"으로 선택하는 기준을 설명하고, `error` 값의 의미를 설명하시오.

```cpp
static Point previousCenter(-1, -1);
static bool firstFrame = true;
const double MAX_DISTANCE = 50.0;
double error = 0.0;

if (firstFrame && !lineCenters.empty()) {
    Point centerOfImage(frame.cols / 2, frame.rows / 2);
    double minDistance = DBL_MAX;
    Point closestCenter;

    for (size_t i = 0; i < lineCenters.size(); i++) {
        double distance = norm(lineCenters[i] - centerOfImage);
        if (distance < minDistance) {
            minDistance = distance;
            closestCenter = lineCenters[i];
        }
    }
    error = centerOfImage.x - closestCenter.x;
    previousCenter = closestCenter;
    firstFrame = false;
}
else if (previousCenter.x != -1 && !lineCenters.empty()) {
    double minDistance = DBL_MAX;
    Point closestCenter;

    for (size_t i = 0; i < lineCenters.size(); i++) {
        double distance = norm(lineCenters[i] - previousCenter);
        if (distance < minDistance && distance < MAX_DISTANCE) {
            minDistance = distance;
            closestCenter = lineCenters[i];
        }
    }

    if (minDistance < MAX_DISTANCE) {
        previousCenter = closestCenter;
    }
    // (거리가 MAX_DISTANCE를 넘으면 previousCenter를 그대로 유지)

    Point centerOfImage(frame.cols / 2, frame.rows / 2);
    error = centerOfImage.x - closestCenter.x;
}
```

<details>
<summary>정답 보기</summary>

첫 프레임(`firstFrame == true`)에서는 기준으로 삼을 이전 위치가 없으므로, 화면 정중앙(`centerOfImage`)에 가장 가까운 블롭을 라인으로 선택합니다. 두 번째 프레임부터는 대신 "직전 프레임에서 선택했던 위치(`previousCenter`)"에 가장 가까운 블롭을 선택하며, 그 거리가 `MAX_DISTANCE`(50.0)를 넘으면 신뢰할 수 없는 후보로 보고 `previousCenter`를 그대로 유지합니다.

이렇게 "이전 프레임과의 연속성"을 기준으로 삼는 이유는, 라인이 갈라지거나(갈림길) 순간적으로 다른 물체가 검출되어도 로봇이 엉뚱한 블롭으로 튀지 않고 부드럽게 원래 라인을 계속 추적하게 하기 위해서입니다.

`error = centerOfImage.x - closestCenter.x`는 "화면 중심의 x좌표"에서 "선택된 라인 중심의 x좌표"를 뺀 값입니다. `error`가 0이면 로봇이 라인 정중앙 위에 있다는 뜻이고, 양수면 라인이 화면 중심보다 왼쪽에, 음수면 오른쪽에 있다는 뜻입니다. 이 값이 실제 라인 트레이서에서 좌우 바퀴 속도를 조절하는 비례 제어(proportional control)의 입력으로 쓰이며, 24장에서 배운 `dxl.setVelocity()` 호출로 이어집니다.

</details>

## 4. 실습과제4 (liner_추가예제/src/pub.cpp)

다음은 라인 검출용 영상을 발행하는 추가 예제 코드이다. 이 코드에서 발견되는 문제점을 지적하고, 왜 문제가 되는지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/compressed_image.hpp"
#include "cv_bridge/cv_bridge.h"
#include "opencv2/opencv.hpp"
#include <memory>
#include <chrono>

std::string src = "nvarguscamerasrc sensor-id=0 ! \
video/x-raw(memory:NVMM), width=(int)640, height=(int)360, \
format=(string)NV12 ! nvvidconv flip-method=0 ! video/x-raw, \
width=(int)640, height=(int)360, format=(string)BGRx ! \
videoconvert ! video/x-raw, format=(string)BGR ! appsink";

int main(int argc, char * argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("campub_8");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)); //TCP
    auto mypub = node->create_publisher<sensor_msgs::msg::CompressedImage>("image/compressed_8", qos_profile );

    std_msgs::msg::Header hdr;
    sensor_msgs::msg::CompressedImage::SharedPtr msg;
    rclcpp::WallRate loop_rate(30.0);

    cv::VideoCapture cap("/home/jetson/simulation/5_lt_cw_100rpm_out.mp4");
    if (!cap.isOpened()) {
        RCLCPP_ERROR(node->get_logger(), "Could not open video!");
        rclcpp::shutdown();
        return -1;
    }

    int w = cvRound(cap.get(CAP_PROP_FRAME_WIDTH));
    int h = cvRound(cap.get(CAP_PROP_FRAME_HEIGHT));

    cv::Mat frame;

    while(rclcpp::ok())
    {
        cap >> frame;
        Mat roi = frame(Rect(0,0,w,h/4))
        if (frame.empty()) { RCLCPP_ERROR(node->get_logger(), "frame empty"); break;}
        msg = cv_bridge::CvImage(hdr, "bgr8", frame).toCompressedImageMsg();
        mypub->publish(*msg);
        loop_rate.sleep();
    }
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

이 코드는 실제로 컴파일이 되지 않는 상태로 남아 있습니다. `Mat roi = frame(Rect(0,0,w,h/4))` 줄 끝에 세미콜론(`;`)이 빠져 있어 문법 오류가 발생합니다. 또한 이 `roi` 변수는 계산만 될 뿐 이후 어디에서도 사용되지 않고, 실제로 발행되는 것은 잘라내지 않은 원본 `frame` 전체입니다 — 즉 "영상 위쪽 1/4만 잘라서 보내려는" 의도로 보이는 코드가 실제로는 그 의도대로 동작하지 않습니다.

또한 파일 상단에 Jetson CSI 카메라용 GStreamer 파이프라인 문자열(`src`)이 정의되어 있지만, 실제로는 `cv::VideoCapture cap("/home/jetson/simulation/5_lt_cw_100rpm_out.mp4")`처럼 저장된 영상 파일을 여는 데 쓰이고 `src` 변수는 어디에도 사용되지 않습니다. 즉 실제 카메라 대신 시뮬레이션용 녹화 영상으로 라인 검출 알고리즘을 테스트하기 위한 코드였음을 알 수 있습니다.

</details>
