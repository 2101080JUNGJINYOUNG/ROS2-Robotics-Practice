## 1. 실습과제1 (다이내믹셀1/main.cpp)

다음은 Dynamixel 모터 2개를 속도 제어로 구동하는 코드이다. `vel1`, `vel2` 값이 시간에 따라 어떻게 변하는지, 그리고 왜 이런 방식으로 구현했는지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "dxl/dxl.hpp"
#include <memory>
#include <chrono>
#include <iostream>
int main(int argc, char * argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("dxl2");
    rclcpp::WallRate loop_rate(10);
    Dxl mx;
    bool a = false;
    int vel1 = 0,vel2 = 0;
    if(!mx.open())
    {
        RCLCPP_INFO(node->get_logger(), "dynamixel open error\n");
        rclcpp::shutdown();
        return -1; //장치열기
    }
    while(rclcpp::ok())
    {
        if(a==false){
            if(vel1+10<401){
                vel1+=10;
                vel2+=10;
            }
            else{
                vel1-=10;
                vel2-=10;
                a = true;
            }
        }
        else{
            if(vel1-10>-401){
                vel1-=10;
                vel2-=10;
            }
            else{
                vel1+=10;
                vel2+=10;
                a = false;
            }
        }
        mx.setVelocity(vel1,vel2);
        RCLCPP_INFO(node->get_logger(),"left speed:%d,right speed:%d",vel1,vel2);
        loop_rate.sleep();
    }
    mx.close();
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

`Dxl mx`는 22장에서 배운 Dynamixel SDK를 감싼 클래스이며, `mx.open()`으로 U2D2를 통해 모터와의 시리얼 통신 포트를 여는 데 실패하면 즉시 에러를 로그로 남기고 프로그램을 종료합니다.

`vel1`, `vel2`는 왼쪽/오른쪽 바퀴의 목표 속도값으로, 매 루프(10Hz)마다 10씩 증가하다가 400을 넘기 직전(`vel1+10<401`이 거짓이 되는 시점)에 방향을 뒤집는 플래그 `a`를 `true`로 바꾸고 이후로는 10씩 감소시키며, 다시 -400 근처에 도달하면 `a`를 `false`로 되돌려 증가로 전환합니다. 즉 속도값이 0 → 400 → -400 → 400 … 사이를 삼각파(triangle wave)처럼 왕복하며 `mx.setVelocity(vel1, vel2)`로 계속 모터에 전달됩니다. 왼쪽과 오른쪽 속도가 항상 같은 값으로 함께 바뀌므로 로봇은 전진과 후진을 반복하는 동작을 하게 되며, 속도를 한 번에 확 바꾸지 않고 10씩 점진적으로 바꾸는 것은 README에서 설명한 것처럼 모터에 무리가 가지 않도록 하는 가감속(ramp) 로직입니다.

</details>

## 2. 실습과제2 (다이내믹셀2/jetson/pub.cpp)

다음은 Jetson Nano에서 카메라 영상을 캡처해 ROS2 토픽으로 발행하는 코드이다. `nvarguscamerasrc`로 시작하는 문자열이 무엇이고, 왜 필요한지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/compressed_image.hpp"
#include "cv_bridge/cv_bridge.h"
#include "opencv2/opencv.hpp"
#include <memory>
#include <chrono>

std::string src = "nvarguscamerasrc sensor-id=0 ! \
video/x-raw(memory:NVMM), width=(int)640, height=(int)360, \
format=(string)NV12 ! nvvidconv flip-method=0 ! video/x-raw, \
width=(int)640, height=(int)360, format=(string)BGRx ! \
videoconvert ! video/x-raw, format=(string)BGR ! appsink";

int main(int argc, char * argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("campub_8");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)); //TCP
    //auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)).best_effort(); //UDP
    auto mypub = node->create_publisher<sensor_msgs::msg::CompressedImage>("image/compressed_8", qos_profile );

    std_msgs::msg::Header hdr;
    sensor_msgs::msg::CompressedImage::SharedPtr msg;
    rclcpp::WallRate loop_rate(30.0);

    cv::VideoCapture cap(src, cv::CAP_GSTREAMER);
    if (!cap.isOpened()) {
        RCLCPP_ERROR(node->get_logger(), "Could not open video!");
        rclcpp::shutdown();
        return -1;
    }
    cv::Mat frame;

    while(rclcpp::ok())
    {
        cap >> frame;
        if (frame.empty()) { RCLCPP_ERROR(node->get_logger(), "frame empty"); break;}
        msg = cv_bridge::CvImage(hdr, "bgr8", frame).toCompressedImageMsg();
        mypub->publish(*msg);
        loop_rate.sleep();
    }
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

`src` 문자열은 22장에서 배운 GStreamer 파이프라인입니다. `nvarguscamerasrc`는 Jetson의 CSI 카메라(IMX219)에서 영상을 읽어오는 소스 엘리먼트이고, 이후 `nvvidconv`(NVIDIA 하드웨어 가속 포맷 변환), `videoconvert`(OpenCV가 다룰 수 있는 BGR 포맷으로 변환)를 거쳐 `appsink`로 끝나 애플리케이션(OpenCV)이 프레임을 받아갈 수 있게 합니다. CSI 카메라는 `cv::VideoCapture(0)`처럼 일반 USB 카메라 방식으로 바로 열리지 않는 경우가 많기 때문에, `cv::VideoCapture(src, cv::CAP_GSTREAMER)`처럼 GStreamer 파이프라인 문자열을 직접 지정해서 여는 방식이 필요합니다.

이렇게 얻은 `frame`(OpenCV `Mat`)은 `cv_bridge::CvImage(...).toCompressedImageMsg()`로 ROS2의 `CompressedImage` 메시지로 변환된 뒤, `image/compressed_8` 토픽에 30Hz로 계속 발행됩니다. QoS는 `KeepLast(10)`(신뢰성 있는 TCP 방식)을 사용하며, 주석 처리된 `.best_effort()`(UDP 방식)로 바꾸면 일부 프레임 유실을 감수하는 대신 지연을 줄이는 실시간 영상 스트리밍에 더 적합한 설정으로 바뀝니다.

</details>

## 3. 실습과제3 (다이내믹셀2/jetson/sub.cpp)

다음은 속도 명령을 구독해 실제 모터를 구동하는 코드이다. `std::bind`가 여기서 어떤 역할을 하는지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/vector3.hpp"
#include "dxl_nano/dxl.hpp"
#include <memory>
#include <functional>
using namespace std::placeholders;

void mysub_callback(rclcpp::Node::SharedPtr node, Dxl& dxl, const geometry_msgs::msg::Vector3::SharedPtr msg)
{
    RCLCPP_INFO(node->get_logger(), "Received message: %lf,%lf", msg->x,msg->y);
    dxl.setVelocity((int)msg->x, (int)msg->y);
}
int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    Dxl dxl;
    auto node = std::make_shared<rclcpp::Node>("node_dxlsub");
    if(!dxl.open())
    {
        RCLCPP_ERROR(node->get_logger(), "dynamixel open error");
        rclcpp::shutdown();
        return -1;
    }
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10));
    std::function<void(const geometry_msgs::msg::Vector3::SharedPtr msg)> fn;
    fn = std::bind(mysub_callback, node, dxl, _1);
    auto mysub = node->create_subscription<geometry_msgs::msg::Vector3>("topic_dxlpub",qos_profile,fn);

    rclcpp::spin(node);

    dxl.close();
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

`mysub_callback`은 `(node, dxl, msg)` 세 개의 인자를 받는 함수인데, `create_subscription`이 요구하는 구독 콜백의 형태는 "메시지 하나만 인자로 받는 함수"입니다. `std::bind(mysub_callback, node, dxl, _1)`은 `node`와 `dxl`을 미리 고정하고, `msg`가 들어올 자리에만 `std::placeholders::_1`을 남겨두어, 실제로 메시지가 도착할 때마다 그 메시지가 `_1` 자리에 채워지며 `void(const geometry_msgs::msg::Vector3::SharedPtr)` 형태로 호출되게 만듭니다.

동작 흐름은, 우분투 PC의 `pub.cpp`가 발행한 속도값(`Vector3`의 `x`, `y`)이 `topic_dxlpub` 토픽으로 도착할 때마다 `mysub_callback`이 자동 호출되고, 그 안에서 `dxl.setVelocity((int)msg->x, (int)msg->y)`를 호출해 실제 Dynamixel 모터의 속도를 즉시 갱신합니다. 즉 네트워크로 전달된 순수한 숫자값(Vector3)이 이 콜백을 거쳐 실제 하드웨어 동작으로 변환되는 지점입니다.

</details>

## 4. 실습과제4 (다이내믹셀2/우분투/pub.cpp)

다음은 키보드 입력으로 로봇을 원격 조종하는 퍼블리셔 코드이다. 왜 목표 속도(`goal1`, `goal2`)와 실제 속도(`vel1`, `vel2`)를 따로 두었는지 설명하시오.

```cpp
// (헤더/선언부 생략: kbhit(), getch() 로 논블로킹 키 입력을 읽는 함수)
int main(int argc, char * argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("node_dxlpub");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10));
    auto mypub = node->create_publisher<geometry_msgs::msg::Vector3>("topic_dxlpub", qos_profile );
    geometry_msgs::msg::Vector3 vel;
    vel.x = 0; vel.y = 0; vel.z = 0;
    rclcpp::WallRate loop_rate(20.0); //20hz->50msec
    int vel1=0,vel2=0;
    int goal1=0,goal2=0;

    while(rclcpp::ok())
    {
        if (kbhit())
        {
            char c = getch();
            switch(c)
            {
            case 's': goal1 = 0; goal2 = 0; break;
            case ' ': goal1 = 0; goal2 = 0; break;
            case 'f': goal1 = 50; goal2 = -50; break;
            case 'b': goal1 = -50; goal2 = 50; break;
            case 'l': goal1 = -50; goal2 = -50; break;
            case 'r': goal1 = 50; goal2 = 50; break;
            default : goal1 = 0; goal2 = 0; break;
            }
        }

        // generate accel and decel motion
        if(goal1>vel1) vel1 += 5;
        else if(goal1<vel1) vel1 -= 5;
        else vel1 = goal1;

        if(goal2>vel2) vel2 += 5;
        else if(goal2<vel2) vel2 -= 5;
        else vel2 = goal2;
        vel.x = vel1;
        vel.y = vel2;

        RCLCPP_INFO(node->get_logger(), "Publish: %lf,%lf", vel.x, vel.y);
        mypub->publish(vel);
        loop_rate.sleep();
    }
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

`goal1`, `goal2`는 키 입력이 들어올 때마다 즉시 바뀌는 "최종 목표 속도"이고, `vel1`, `vel2`는 실제로 발행되는 "현재 속도"입니다. 예를 들어 `f`(전진)를 누르면 `goal1 = 50, goal2 = -50`으로 즉시 바뀌지만, `vel1`/`vel2`는 매 루프(20Hz, 50ms)마다 목표값과 비교해 `goal`보다 작으면 5씩 증가, 크면 5씩 감소하며 서서히 목표값에 접근합니다. 만약 목표 속도를 그대로 즉시 발행했다면 정지 상태에서 갑자기 최고 속도로 명령이 튀어 모터·기어에 무리가 가거나 로봇이 급발진하듯 움직일 수 있는데, 이렇게 `goal`과 `vel`을 분리해 매 루프 조금씩만 접근시키는 방식이 1번 문제(`다이내믹셀1/main.cpp`)에서 본 것과 같은 가감속(ramp) 로직입니다. `f`(전진), `b`(후진), `l`(좌회전), `r`(우회전), `s`/스페이스(정지) 키에 따라 좌우 바퀴의 목표 속도 부호를 다르게 설정해 방향을 구분합니다.

</details>

## 5. 실습과제5 (다이내믹셀2/우분투/sub.cpp)

다음은 Jetson Nano가 보낸 카메라 영상을 받아 화면에 띄우고 녹화하는 코드이다. 이 노드가 멈추거나 창을 닫아도 로봇 주행에 영향이 없는 이유를 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/compressed_image.hpp"
#include "opencv2/opencv.hpp"
#include <memory>
#include <functional>
#include <iostream>
using std::placeholders::_1;

cv::VideoWriter recorder("save.mp4",cv::VideoWriter::fourcc('X','2','6','4'),30,cv::Size(640,360));
void mysub_callback(rclcpp::Node::SharedPtr node, const sensor_msgs::msg::CompressedImage::SharedPtr msg)
{
    cv::Mat frame = cv::imdecode(cv::Mat(msg->data), cv::IMREAD_COLOR);
    cv::imshow("gray",frame);
    cv::imshow("throshed",frame);
    cv::imshow("wsl",frame);
    recorder.write(frame);
    cv::waitKey(1);
    RCLCPP_INFO(node->get_logger(), "Received Image : %s,%d,%d", msg->format.c_str(),frame.rows,frame.cols);
}
int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("camsub_wsl_8");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)); //TCP
    //auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)).best_effort(); //UDP
    std::function<void(const sensor_msgs::msg::CompressedImage::SharedPtr msg)> fn;
    fn = std::bind(mysub_callback, node, _1);
    auto mysub = node->create_subscription<sensor_msgs::msg::CompressedImage>("image/compressed_8",qos_profile,fn);
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

이 노드는 `image/compressed_8` 토픽(카메라 영상)만 구독하며, `cv::imdecode`로 압축 해제한 프레임을 `cv::imshow`로 화면에 띄우고 `recorder.write(frame)`로 `save.mp4`에 녹화하는 것이 전부입니다. 즉 모터를 제어하는 `topic_dxlpub` 토픽이나 `dxl.setVelocity()` 호출과는 전혀 연결되어 있지 않은, README에서 설명한 것처럼 순수한 "모니터링용" 노드입니다.

실제로 로봇을 움직이는 경로는 우분투의 `pub.cpp`(키보드 입력 → `topic_dxlpub` 발행) → Jetson의 `jetson/sub.cpp`(구독 → `dxl.setVelocity()` 호출)로 완전히 독립된 별개의 노드/토픽 흐름입니다. 따라서 이 영상 확인용 노드가 죽거나 창을 닫아도 모터 제어 경로에는 아무 영향이 없으며, 이렇게 관심사(모터 제어와 영상 모니터링)를 분리해두는 것이 한쪽에 문제가 생겨도 다른 쪽이 안전하게 계속 동작하도록 하는 설계 원칙입니다.

</details>
