### 1. 실습과제1 (rclcpp/project1)

다음 퍼블리셔 코드를 분석하고, 각 줄이 어떤 역할을 하는지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/int32.hpp"
#include <memory>
#include <chrono>
int main(int argc, char * argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("node_pub2");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10));
    auto mypub = node->create_publisher<std_msgs::msg::Int32>("topic_pub2", qos_profile);
    std_msgs::msg::Int32 message;
    message.data = 0;
    rclcpp::WallRate loop_rate(1.0);
    while(rclcpp::ok())
    {
        RCLCPP_INFO(node->get_logger(), "Publish: %d", message.data++);
        mypub->publish(message);
        loop_rate.sleep();
    }
    rclcpp::shutdown();
    return 0;
}
```

### 3. 실습과제3 (rclcpp/project3)

다음 퍼블리셔 코드를 분석하고, 어떤 로봇 제어 상황에 쓰일 수 있는지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"

int main(int argc, char * argv[])
{
    char a;
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("node_pub1_3");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10));
    auto mypub = node->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", qos_profile);
    geometry_msgs::msg::Twist message;
    rclcpp::WallRate loop_rate(1.0);
    while(rclcpp::ok())
    {
        std::cin >> a;

        message.linear.x = 0.0;
        message.linear.y = 0.0;
        message.linear.z = 0.0;
        message.angular.x = 0.0;
        message.angular.y = 0.0;
        message.angular.z = 0.0;

        switch(a)
        {
        case 'f': // 전진
            message.linear.x =3.0;
            break;
        case 'b': // 후진
            message.linear.x =-3.0;
            break;
        case 'l': // 왼쪽으로 돔
            message.angular.z =3.0;
            break;
        case 'r': // 오른쪽으로 돔
            message.angular.z =-3.0;
            break;
        }
        if((a=='f')||(a=='b')||(a=='l')||(a=='r')){
            RCLCPP_INFO(node->get_logger(), "Publish: %c 키 누름", a);
            mypub->publish(message);
        }
        a = '0';
        loop_rate.sleep();
    }
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

이 코드는 `geometry_msgs::msg::Twist`(선속도 `linear`, 각속도 `angular`) 메시지를 `/turtle1/cmd_vel` 토픽으로 발행하는 키보드 조작 퍼블리셔입니다. `/turtle1/cmd_vel`은 turtlesim 시뮬레이터의 거북이를 움직이는 표준 토픽 이름으로, 매 루프마다 한 글자(`f`/`b`/`l`/`r`)를 입력받아 `switch`문으로 분기합니다. `f`는 전진(`linear.x = 3.0`), `b`는 후진(`linear.x = -3.0`), `l`은 좌회전(`angular.z = 3.0`), `r`은 우회전(`angular.z = -3.0`)에 해당하며, 매 루프 시작 시 6개 필드를 모두 0으로 초기화한 뒤 필요한 값만 설정해 이전 입력값이 남아있지 않도록 합니다. 정의된 4개의 키가 아니면 아무 것도 발행하지 않는 것도 특징입니다. 이런 구조는 turtlesim이나 실제 이동 로봇을 키보드로 원격 조종(teleop)할 때 그대로 활용할 수 있습니다.

</details>

## 2회차 — rclcpp2/ (std::bind + create_wall_timer)

### 4. 실습과제4 (rclcpp2/project1)

다음 코드를 분석하고, `while(rclcpp::ok())` 방식과 비교했을 때 구조가 어떻게 달라졌는지 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/int32.hpp"
#include <memory>
#include <chrono>
#include <functional>
using namespace std::chrono_literals;
void callback(rclcpp::Node::SharedPtr node,
    rclcpp::Publisher<std_msgs::msg::Int32>::SharedPtr mypub)
{
    static int count=0;
    auto message = std_msgs::msg::Int32();
    message.data = count++;
    RCLCPP_INFO(node->get_logger(), "Publish: %d", message.data);
    mypub->publish(message);
}
int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("mynode");
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10));
    auto pub = node->create_publisher<std_msgs::msg::Int32>("mytopic", qos_profile);
    std::function<void()> fn = std::bind(callback, node, pub);
    auto timer = node->create_wall_timer(100ms, fn);
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

1회차 코드는 개발자가 직접 `while(rclcpp::ok())` 루프를 돌며 발행과 `sleep`을 반복했지만, 이 코드는 발행 로직을 `callback` 함수로 분리하고 `create_wall_timer(100ms, fn)`으로 "100ms마다 자동 호출해달라"고 등록한 뒤 `rclcpp::spin(node)`로 대기합니다. 즉 언제 콜백을 호출할지의 제어권이 개발자 코드가 아니라 rclcpp 프레임워크로 넘어간 것(제어의 역전, IoC)이 핵심 차이입니다. `callback`은 원래 `(node, mypub)` 두 개의 인자를 받는데, 타이머가 기대하는 콜백 형태는 인자가 없는 `void()` 함수이므로 `std::bind(callback, node, pub)`로 두 인자를 미리 고정해 인자 없이 호출 가능한 `fn`을 만들어 전달합니다. `count`는 `static`으로 선언되어 콜백이 호출될 때마다 값이 유지되며 1씩 증가합니다.

</details>

다음 코드를 분석하고, `실습과제2`(rclcpp/project2)의 사용자 입력 방식과 이 코드의 콜백 방식을 비교해서 설명하시오.

```cpp

```

<details>
<summary>정답 보기</summary>

`rclcpp/project2`는 `while` 루프 안에서 `std::cin`으로 값을 입력받은 뒤 즉시 발행하는 흐름이 반복문 자체에 그대로 드러나 있었지만, 이 코드는 같은 입력·발행 로직을 `callback` 함수 안으로 옮기고 `create_wall_timer(100ms, fn)`으로 100ms마다 이 콜백이 자동 호출되도록 등록했습니다. 즉 "언제 입력을 받고 발행할지"의 타이밍을 개발자가 while문으로 직접 제어하는 대신, rclcpp의 타이머 스케줄러가 대신 호출해주는 구조로 바뀐 것입니다(단, 이 코드는 `std::cin`이 콜백 안에 있어 실제로는 입력을 기다리는 동안 타이머 주기가 그대로 지켜지지는 않는다는 한계도 있습니다). `std::bind(callback, node, pub)`로 `node`와 `pub`을 미리 고정해 타이머가 요구하는 인자 없는 콜백 형태(`std::function<void()>`)로 맞춰준 것은 4번 문제와 동일한 패턴입니다.

</details>

### 6. 실습과제6 (rclcpp2/project3)

다음 코드를 분석하고 설명하시오.

```cpp
#include "rclcpp/rclcpp.hpp" // ROS 2 C++ 클라이언트 라이브러리
#include "geometry_msgs/msg/twist.hpp" // 발행할 메시지 타입
#include <chrono> // 시간 관련 기능을 사용
#include <functional> // std::bind, std::function 등을 사용

using namespace std::chrono_literals; // 100ms와 같은 시간 리터럴 사용을 위함
void callback(rclcpp::Node::SharedPtr node,
    rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr mypub) // 100ms마다 호출되어 메시지를 발행하는 콜백 함수
{
    static auto message = geometry_msgs::msg::Twist(); // 발행할 Twist 메시지 객체 생성 및 초기화
    message.linear.x = 2; // 값 설정
    message.angular.z = 2; // 값 설정
    RCLCPP_INFO(node->get_logger(), "Publish"); // ROS 2 로깅 시스템을 사용하여 현재 발행하는 데이터를 출력
    mypub->publish(message); // 준비된 메시지 객체를 mytopic에 발행
}

int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv); // ROS 2 시스템 초기화
    auto node = std::make_shared<rclcpp::Node>("mynode"); //노드 객체 생성
    auto qos_profile = rclcpp::QoS(rclcpp::KeepLast(10)); // Qos설정
    auto pub = node->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", qos_profile); // topic설정
    std::function<void()> fn = std::bind(callback, node, pub); // 콜백 함수
    auto timer = node->create_wall_timer(100ms, fn); // 타이머 생성
    rclcpp::spin(node); // 대기
    rclcpp::shutdown(); // 종료
    return 0;
}
```

<details>
<summary>정답 보기</summary>

`실습과제3`(rclcpp/project3)이 키보드 입력에 따라 4방향 중 하나로 값을 바꿔가며 발행했다면, 이 코드는 사용자 입력 없이 `linear.x = 2`, `angular.z = 2`로 고정된 값을 `/turtle1/cmd_vel`에 100ms마다 계속 발행합니다. 그 결과 turtlesim의 거북이는 일정한 선속도와 각속도로 계속 원을 그리며 이동하게 됩니다. `message`가 `static`으로 선언되어 있어 콜백이 여러 번 호출되어도 값 설정은 그대로 유지되며, `std::bind(callback, node, pub)`로 타이머 콜백 형태에 맞춘 것은 앞선 rclcpp2 문제들과 동일한 패턴입니다.

</details>

### 7. 실습과제7 (rclcpp3/project1)

다음은 서로 다른 실행 파일로 분리된 퍼블리셔(`pub.cpp`)와 서브스크라이버(`sub.cpp`) 코드이다. 두 파일이 어떻게 연결되어 동작하는지 설명하시오.

```cpp
// pub.cpp
#include"rclcpp/rclcpp.hpp"
#include"std_msgs/msg/string.hpp"
#include"rclcpp/time_source.hpp"
#include<memory>
#include<chrono>
using namespace std::chrono_literals;
void callback(rclcpp::Node::SharedPtr node,
    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr mypub)
{
    static auto message = std_msgs::msg::String();
    message.data = "Hello World!!";
    RCLCPP_INFO(node->get_logger(), "Publish: %s", message.data.c_str());
    mypub->publish(message);
}

int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    auto node=std::make_shared<rclcpp::Node>("node_pub1");
    auto qos_profile=rclcpp::QoS(rclcpp::KeepLast(10));
    auto mypub=node->create_publisher<std_msgs::msg::String>("topic_pub1", qos_profile);
    std::function<void()> fn = std::bind(callback, node, mypub);
    auto timer = node->create_wall_timer(100ms, fn);
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

```cpp
// sub.cpp
#include"rclcpp/rclcpp.hpp"
#include"std_msgs/msg/string.hpp"
#include<memory>
#include<functional>

void mysub_callback(rclcpp::Node::SharedPtr node, const std_msgs::msg::String::SharedPtr msg)
{
    RCLCPP_INFO(node->get_logger(), "Received message: %s", msg->data.c_str());
}

int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
```

<details>
<summary>정답 보기</summary>

두 코드는 `"topic_pub1"`이라는 같은 토픽 이름을 통해 연결됩니다. `pub.cpp`는 `node_pub1` 노드를 만들어 `create_wall_timer(100ms, fn)`으로 100ms마다 `callback`이 호출되게 하고, 그 안에서 `"Hello World!!"` 문자열을 담은 `std_msgs::msg::String` 메시지를 `topic_pub1`에 발행합니다. `sub.cpp`는 `node_sub1`이라는 별개의 노드를 만들어 같은 `"topic_pub1"` 토픽을 `create_subscription`으로 구독하며, 메시지가 도착할 때마다 `mysub_callback`이 자동 호출되어 수신한 문자열을 로그로 출력합니다.

두 콜백 모두 `std::bind`로 인자를 맞춰주는 패턴이 쓰였는데, 퍼블리셔 쪽은 `callback(node, mypub)`의 두 인자를 모두 고정해 타이머가 요구하는 인자 없는 `void()` 형태로 만들었고, 구독 쪽은 `mysub_callback(node, msg)`에서 `node`만 고정하고 `msg` 자리에는 `std::placeholders::_1`을 남겨두어, 메시지가 도착할 때마다 그 메시지가 `_1` 자리에 채워지며 호출되는 `void(const std_msgs::msg::String::SharedPtr)` 형태로 만들었습니다. 두 노드는 완전히 별개의 프로세스(실행 파일)로 실행되며, ROS2의 토픽 기반 발행-구독 구조 덕분에 서로 직접 참조하지 않고도 통신할 수 있습니다.

</details>

### 8. 실습과제8 (rclcpp3/project2)

다음은 정수형 메시지를 주고받는 퍼블리셔/서브스크라이버 쌍이다. `실습과제7`(String 버전)과 비교하여 달라진 점을 설명하시오.

```cpp
// pub.cpp
#include"rclcpp/rclcpp.hpp"
#include"std_msgs/msg/int32.hpp"
#include"rclcpp/time_source.hpp"
#include<memory>
#include<chrono>
using namespace std::chrono_literals;
void callback(rclcpp::Node::SharedPtr node,
    rclcpp::Publisher<std_msgs::msg::Int32>::SharedPtr mypub)
{
    static auto message = std_msgs::msg::Int32();
    RCLCPP_INFO(node->get_logger(), "Publish: %d", message.data++);
    mypub->publish(message);
}

int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    auto node=std::make_shared<rclcpp::Node>("node_pub1");
    auto qos_profile=rclcpp::QoS(rclcpp::KeepLast(10));
    auto mypub=node->create_publisher<std_msgs::msg::Int32>("topic_pub1", qos_profile);
    std::function<void()> fn = std::bind(callback, node, mypub);
    auto timer = node->create_wall_timer(50ms, fn);
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

```cpp
// sub.cpp
#include"rclcpp/rclcpp.hpp"
#include"std_msgs/msg/int32.hpp"
#include<memory>
#include<functional>

void mysub_callback(rclcpp::Node::SharedPtr node, const std_msgs::msg::Int32::SharedPtr msg)
{
    RCLCPP_INFO(node->get_logger(), "Received message: %d", msg->data);
}

int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("node_sub1");
    auto qos_profile= rclcpp::QoS(rclcpp::KeepLast(10));

    std::function<void(const std_msgs::msg::Int32::SharedPtr)> fn = std::bind(mysub_callback, node, std::placeholders::_1);
    auto mysub= node->create_subscription<std_msgs::msg::Int32>("topic_pub1",qos_profile,fn);

    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

<details>
<summary>정답 보기</summary>

전체 구조(타이머 콜백으로 발행, `std::bind`로 콜백 인자 맞추기, 같은 토픽 이름으로 구독)는 `실습과제7`과 완전히 동일하지만, 두 가지가 달라졌습니다. 첫째, 메시지 타입이 `std_msgs::msg::String`에서 `std_msgs::msg::Int32`로 바뀌어, 문자열 대신 정수 하나(`data`)를 주고받습니다. `message`가 `static`으로 선언되어 있고 `message.data++`로 후위 증가하므로, 호출될 때마다 0부터 1씩 증가하는 값이 발행됩니다. 둘째, 타이머 주기가 `100ms`에서 `50ms`로 절반이 되어, 초당 발행 빈도가 약 10Hz에서 약 20Hz로 늘어났습니다. 서브스크라이버 쪽 역시 메시지 타입만 `Int32`에 맞게 바뀌었을 뿐, `std::bind`로 `msg` 자리를 `std::placeholders::_1`로 남겨두는 콜백 구성 패턴은 동일합니다.

</details>
