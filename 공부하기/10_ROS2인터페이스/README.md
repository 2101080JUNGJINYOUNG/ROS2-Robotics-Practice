# 10장. ROS2 인터페이스 — 공부하기

이 챕터는 "메시지, 토픽, 서비스, 액션, 인터페이스"라는 다섯 용어를 구분하고, 실제 인터페이스 구조를 조회해보는 실습입니다. 이 용어들은 뒤에 나오는 모든 챕터(특히 18~20장 rclcpp)에서 계속 등장하므로 여기서 확실히 구분해두면 이후 학습이 훨씬 수월해집니다.

## 1. 인터페이스(Interface) — 데이터의 "설계도"

인터페이스는 ROS2에서 노드 간에 주고받는 데이터의 구조(형식)를 정의한 것입니다. `.msg`(메시지용), `.srv`(서비스용), `.action`(액션용) 세 종류의 파일로 정의됩니다. 예를 들어 `geometry_msgs/msg/Twist`는 `.msg` 파일로 정의된 인터페이스이고, 그 안에 `linear`, `angular`라는 필드가 있다고 미리 약속되어 있는 것입니다. 인터페이스는 "이 데이터는 어떤 필드를 가지고 있다"는 설계도 역할만 하고, 실제로 이 데이터가 어떻게 전달되는지는 통신 방식(토픽/서비스/액션)이 결정합니다.

## 2. 메시지(Message) — 토픽 통신의 데이터 단위

메시지는 토픽을 통해 오가는 데이터 그 자체를 가리키는 말입니다. `.msg` 파일로 정의된 구조를 따르는 실제 데이터 인스턴스라고 생각하면 됩니다.

## 3. 토픽(Topic) — 1:다 비동기 통신

앞선 챕터(06장)에서 다룬 대로, 발행자가 계속 흘려보내고 구독자가 원할 때 받는 방식입니다. 발행자와 구독자 수에 제한이 없고(1:다, 다:다 모두 가능), 응답을 기다리지 않는 비동기(asynchronous) 통신입니다.

## 4. 서비스(Service) — 1:1 동기 요청/응답

서비스는 "질문을 보내면 답을 받을 때까지 기다리는" 방식의 통신입니다. 클라이언트가 요청(Request)을 보내면 서버가 처리해서 응답(Response)을 돌려줄 때까지 기다립니다(동기, synchronous). 함수를 호출하고 리턴값을 받는 것과 비슷한 구조입니다. `.srv` 파일은 요청 필드와 응답 필드가 `---` 구분선으로 나뉘어 정의됩니다. "센서 값이 몇 초마다 계속 필요한 것"은 토픽이 맞고, "한 번 물어보고 답만 받으면 되는 것"(예: 지도 저장, 파라미터 조회)은 서비스가 적합합니다.

## 5. 액션(Action) — 시간이 오래 걸리는 비동기 작업

액션은 "결과가 나오기까지 시간이 오래 걸리는 작업"을 위한 통신 방식입니다. 서비스처럼 결과를 기다리는 것은 같지만, 그 사이에 중간 진행 상황(feedback)을 계속 받을 수 있고 중간에 취소도 가능하다는 점이 다릅니다. 액션은 세 부분으로 구성됩니다.

- **Goal(목표)**: "이 위치로 이동해줘" 같은, 클라이언트가 요청하는 최종 목표
- **Feedback(중간 진행상황)**: "지금 70% 이동했어" 같은, 작업이 진행되는 동안 계속 보내주는 중간 상태
- **Result(최종 결과)**: 작업이 끝났을 때 최종적으로 돌려주는 결과값

예를 들어 "로봇을 목적지까지 이동시켜라"는 몇 초~몇 분이 걸릴 수 있고 중간 경과(현재 위치)를 계속 알고 싶으므로 액션이 적합하고, "현재 위치가 어디야?"는 즉시 답할 수 있으므로 서비스가 적합합니다.

## 6. 세 통신 방식 비교 정리

| 방식 | 관계 | 동기/비동기 | 언제 쓰는가 |
|---|---|---|---|
| 토픽 | 1:다 | 비동기 | 센서 값처럼 계속 흘러나오는 데이터 |
| 서비스 | 1:1 | 동기(응답 대기) | 한 번 요청하고 바로 답 받는 작업 |
| 액션 | 1:1 | 비동기 + 중간 피드백 | 오래 걸리고 중간 진행상황이 필요한 작업 |

## 7. `ros2 interface show`로 실제 구조 조회하기

```
ros2 topic list -t                          # 토픽 이름과 타입 확인
ros2 interface show geometry_msgs/msg/Twist  # 해당 인터페이스의 실제 필드 구조 출력
```

`ros2 interface show <타입>` 명령을 실행하면 그 인터페이스가 어떤 필드로 구성되어 있는지 텍스트로 그대로 보여줍니다. 예를 들어 `turtlesim/msg/Pose`를 조회하면 `x`, `y`, `theta`, `linear_velocity`, `angular_velocity` 필드가 나오는데, 이걸 통해 "turtlesim 노드가 거북이의 위치와 각도, 속도를 이런 필드로 발행하고 있구나"를 코드를 보지 않고도 알 수 있습니다. 이 명령은 앞으로 새로운 메시지 타입을 다룰 때마다 "이 메시지 안에 어떤 필드가 있는지" 확인하는 가장 기본적인 방법이므로, 18~20장·24~25장 코드를 읽을 때도 계속 쓰게 됩니다.

## 8. 스스로 확인하는 질문

- 토픽/서비스/액션 중 어떤 걸 써야 할지, 아래 세 상황에 각각 답해보기: (1) 카메라 영상을 계속 화면에 뿌려야 한다 (2) 로봇에게 "지금 배터리 몇 %야?" 물어봐야 한다 (3) 로봇에게 "저기까지 이동해"라고 시키고 중간에 얼마나 갔는지도 보고 싶다.
- `.msg`, `.srv`, `.action` 파일이 각각 무엇을 정의하는가?
- `ros2 interface show`는 왜 필요한가? (코드를 직접 보지 않고도 무엇을 알 수 있는가)
