## 11_CMake사용법-1

### 1-1. CMake와 GNU Make의 차이점을 설명하라.

<details>
<summary>정답 보기</summary>

CMake와 GNU Make의 가장 큰 차이점은 역할과 추상화 수준에 있습니다. CMake는 다양한 운영체제에서 사용할 수 있는 크로스 플랫폼 빌드 시스템 생성 도구(Cross Platform Make)입니다. 개발자가 작성한 CMakeLists.txt 파일을 바탕으로 리눅스의 Makefile, 윈도우의 Visual Studio 프로젝트 파일 등 각 플랫폼에 맞는 네이티브 빌드 파일을 생성하는 역할을 합니다. 반면, GNU Make는 Makefile의 내용을 직접 해석하여 소스 코드를 컴파일하고 링크하는 등 실제 빌드 과정을 수행하는 도구입니다. 즉, CMake는 어떤 환경에서든 동일한 방식으로 빌드 설정을 할 수 있게 해주는 상위 레벨의 '설계자'이고, GNU Make는 특정 환경(리눅스)에서 그 설계도(Makefile)를 보고 실제로 빌드를 실행하는 하위 레벨의 '작업자'입니다.

</details>

### 1-2. CMakeLists.txt의 역할을 설명하라.

<details>
<summary>정답 보기</summary>

CMakeLists.txt는 CMake 프로젝트의 핵심적인 프로젝트 설정 파일로서, 개발자가 프로젝트를 어떻게 빌드할지 기술하는 설계도의 역할을 합니다. 이 파일 안에는 프로젝트의 이름, 컴파일할 소스 파일 목록, 그리고 프로젝트가 의존하는 외부 라이브러리 정보와 같은 빌드에 필요한 최소한의 정보가 담겨 있습니다. CMake는 Configure 단계에서 가장 먼저 이 파일을 해석하여 프로젝트의 전체 구조와 의존성을 파악하고, 이를 바탕으로 시스템에 맞는 빌드 파일들을 생성하기 때문에, CMakeLists.txt는 전체 빌드 과정의 시작점이자 가장 중요한 입력 파일이라고 할 수 있습니다.

</details>

### 1-3. CMakeCache.txt의 역할을 설명하라.

<details>
<summary>정답 보기</summary>

CMakeCache.txt는 CMake가 Configure 단계를 실행할 때 시스템 환경을 분석한 뒤, 그 탐지 결과를 저장하기 위해 자동으로 생성하는 캐시 파일입니다. 이 파일에는 C/CXX 컴파일러의 경로, 시스템에 설치된 라이브러리의 위치, 사용자가 설정한 빌드 옵션 등 빌드에 필요한 다양한 환경 변수와 경로 정보가 기록됩니다. 한번 이 파일이 생성되고 나면, CMake는 다시 실행될 때마다 시스템 환경을 처음부터 탐색하는 대신 CMakeCache.txt에 저장된 값을 우선적으로 읽어오므로, 반복적인 빌드 과정의 속도를 향상시키는 역할을 합니다.

</details>

### 1-4. CMake의 각 단계별(configure->generate->build) 결과물을 자세히 설명하라.

<details>
<summary>정답 보기</summary>

CMake의 빌드 과정은 세 단계로 나뉘며 각 단계의 결과물은 명확하게 구분됩니다. 첫 번째 Configure 단계에서는 CMakeLists.txt를 해석하고 시스템 환경을 분석하여, 그 결과물로 탐지된 컴파일러 및 라이브러리 경로 정보가 담긴 CMakeCache.txt 파일과 초기 빌드 트리를 생성합니다.

두 번째 Generate 단계에서는 Configure 단계의 결과를 바탕으로, 리눅스의 Makefile이나 윈도우의 Visual Studio 솔루션 파일과 같이 현재 운영체제에서 사용되는 네이티브 빌드 도구에 맞는 프로젝트 파일을 생성합니다.

마지막 Build 단계에서는 Generate 단계에서 만들어진 Makefile 등을 실제 빌드 도구(예: make)로 실행하여, 소스 코드를 컴파일하고 링크한 최종 결과물인 실행 파일 또는 라이브러리를 생성합니다.

</details>

> 원본 과제 PDF에는 이 "예제1"의 실제 내용(코드, CMakeLists.txt)이 별도로 수록되어 있지 않고, 바로 아래 1-5번 문제에서 "예제1에서..."라고 참조만 하고 있습니다. 아래는 1-5번 문제의 정답 화면(실행 파일 이름 `Hello`, 출력 `Hello World!`, `hello/build` 디렉토리 구조)에 나온 결과가 그대로 나오도록 원본 예제의 코드를 역으로 재구성한 것입니다.

## 11_CMake사용법-2

### 1. 실습과제1 — CMake를 이용하여 레나영상을 그레이영상, 이진영상으로 변환하여 출력하는 프로그램을 작성하시오.

원본 이미지, 그레이스케일 이미지, 이진(흑백) 이미지 세 개의 창을 띄우는 OpenCV 프로그램을 작성하는 문제였습니다.

<details>
<summary>정답 보기</summary>

**main.cpp**

```cpp
#include "opencv2/opencv.hpp"   // opencv 헤더파일 포함
#include <iostream>             // iostream 포함
using namespace std;            // std를 생략하기 위해 사용
using namespace cv;             // cv를 생략하기 위해 사용

int main()
{
    Mat img,grayscale,bin;               // Mat 객체 3개 생성
    img = imread("../source/lenna.bmp"); // lenna.bmp를 읽어옴
    if(img.empty()){cerr << "Image load failed!"<<endl; return -1; } // 이미지를 못 읽어 경우 에러메세지 출력
    cvtColor(img,grayscale,COLOR_BGR2GRAY);           // 컬러 이미지를 흑백 이미지로 변환하여 grayscale에 저장
    threshold(grayscale,bin,0,255,THRESH_BINARY | THRESH_OTSU); // 흑백이미지를 이진영상 변환하여 bin에 저장
    imshow("img",img);                   //img를 화면에 띄움
    imshow("grayscale",grayscale);       // grayscale을 화면에 띄움
    imshow("bin",bin);                   // bin을 화면에 띄움
    waitKey();                           // 입력 대기
}
```

**CMakeLists.txt**

```cmake
# CMake의 최소 요구 버전을 지정한다.
# 여기서는 CMake 3.16.3 이상이 필요하다는 의미.
cmake_minimum_required(VERSION 3.16.3)

# 프로젝트 이름을 지정한다.
# 이 프로젝트의 이름은 "HelloCV".
project(HelloCV)

# OpenCV 라이브러리를 찾는다.
# OpenCV가 시스템에 설치되어 있어야 하며, CMake가 경로를 자동으로 찾아준다.
find_package(OpenCV REQUIRED)

# 실행 파일을 생성한다.
# "HelloCV"라는 이름의 실행 파일을 만들고, main.cpp 파일을 컴파일 대상으로 한다.
add_executable(HelloCV main.cpp)

# 타겟(HelloCV)에 include 디렉토리를 추가한다.
# ${OpenCV_INCLUDE_DIRS}는 OpenCV 헤더 파일이 위치한 디렉토리 경로를 의미한다.
target_include_directories(HelloCV PUBLIC ${OpenCV_INCLUDE_DIRS})

# 타겟(HelloCV)에 링크할 라이브러리를 지정한다.
# ${OpenCV_LIBS}는 OpenCV에서 제공하는 필요한 라이브러리 목록을 의미한다.
target_link_libraries(HelloCV PUBLIC ${OpenCV_LIBS})
```

**실행결과**

```
linux@JINYOUNG:~/hellocv/build$ ./HelloCV
Hello OpenCV 4.2.0
linux@JINYOUNG:~/hellocv/build$ ./HelloCV
Hello OpenCV 4.2.0
```

실행하면 원본(image), 그레이스케일(gray), 이진화(brightness) 세 개의 창이 뜨며, 이진화 창은 오츠(OTSU) 알고리즘으로 자동 임계값을 구해 흑백으로 이진화된 결과를 보여줍니다.

</details>
